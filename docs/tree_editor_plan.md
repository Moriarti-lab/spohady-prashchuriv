## 1. Що є зараз (аудит)

### 1.1 HTML-редактор (`tools/tree-editor/index.html`)

| Можливість | Стан |
|------------|------|
| Pan / pinch / wheel zoom, Fit | Є (після 0.5.4 min zoom 0.005, snap 100, сітка 1000) |
| Режими Рух / Зв’язки / Додати вузол | Є (явні режими — добре для тачу) |
| Undo / Redo | Є (історія в пам’яті + `localStorage`) |
| Редагування id/name/description/type/region/icon/stats | Є |
| Каталог бонусів `STAT_KEYS` | **58** ключів (жорстко вшиті в HTML) |
| `MOD_KEYS` (науз-моди) | 10 ключів — для застарілих `mod_skill`/`mods` |
| Валідація | Є: унікальні id, зв’язки, типи, ключі stats, class_starts, острови (warning) |
| Import / Export JSON | Є (download + textarea); формат = `data/perk_tree.json` |
| Sync у репо | `python3 tools/sync_editor_tree.py` вбудовує JSON у HTML |
| Тести | `node tools/test_editor.js` (+ опційний jsdom UI) |
| В APK / Godot | **Ні** — лише файл для браузера/ПК |
| Українські підписи одиниць у полях stats | Слабко: ключі англійські в інпутах, без діапазонів |

### 1.2 Завантаження в грі

- `PerkTree` (`scripts/data/perk_tree.gd`): читає `res://data/perk_tree.json`, версії 1–4; відкидає невідомі ключі stats (лише ті, що є в `STAT_TEXT`).
- Fallback `default_tree()` якщо файл битий.
- UI: `PerkTreeView` / `PerkTreeScreen` (pan/zoom/focus), **не** редактор.
- Збереження героя: `user://` слоти — **окремо** від JSON Древа.

### 1.3 Реєстри текстів і дрифт

| Джерело | Роль |
|---------|------|
| `PerkTree.STAT_TEXT` / `STAT_ORDER` | Описи в грі + валідація ключів при load |
| HTML `STAT_KEYS` / `MOD_KEYS` | Валідація/UI редактора |
| `Skills.MOD_TEXT` / `Nauzi` mods | Моди наузів/ниток (не вузли Древа) |
| `DescFormat` | BBCode з `STAT_TEXT` |

**Дрифт уже є:** у грі `STAT_TEXT` ширший за HTML `STAT_KEYS` (напр. `radius_pct`, `range_pct`, `duration_pct`, `cd_pct`, `count`, `power_pct`, `heal_pct`, `stun`, плюс поля зброї `dmg`/`interval`/`range`/`arc`). Редактор **не показує** ці ключі як бонуси вузла; гра їх може показувати в описах предметів/наузів.

Машинний каталог: [`docs/tree_stat_catalogue.json`](tree_stat_catalogue.json).

### 1.4 Що реально працює в механіці

`HeroStats.bonus(key)` = сума з **розблокованих вузлів** + спорядження + бафів.  
Окремо `tree_sum("xp_pct")` для звитяги.

**Підключені до формул (перевірено в коді):** `str`/`agi`/`faith`, `hp`/`hp_pct`, `mana_*`, `armor`, `dmg_pct`, `atk_speed_pct`, `crit_pct`/`crit_dmg_pct`, `cdr_pct`, `lifesteal_pct`, `thorns_pct`, `dr_pct`, `move_pct`, `dodge_pct`, `block_pct`/`block_power_pct`, `aoe_pct`, `effect_dur_pct`, `skill_cost_pct`, `gold_pct`, `drop_pct`, `xp_pct`, `nauz_xp_pct`, `nauz_level`, `thread_power_pct`, прапорці `one_path`, `free_skills`, `block_no_shield`. Повний список — у каталозі (`mechanics_wired`).

**У STAT_TEXT без знайдених викликів у бою (приклади):** `life_pay_skills`, `crit_stun`, `kill_haste`, `res_*`, `pen_*`, `life_on_kill`, `double_hit_pct` — `registry_display_only`.

**У реєстрі / описах, але без знайденого бойового застосування** (потрібна окрема робота в грі, якщо «увімкнути»): опори `res_*`, пробиття `pen_*` / `armor_pen_pct`, `double_hit_pct`, `proj_speed_pct`, `life_on_kill`, `mana_on_kill`, `stun_chance_pct`, `nauz_thread_slots`, тощо — див. `availability: registry_display_only` у каталозі.

**Важливо:** ключі на кшталт `radius_pct` на **вузлі Древа** зараз **не** потрапляють у `HeroStats.skill_params` (радіус умінь з Древа йде через `aoe_pct`). `radius_pct` живе в контурі **наузів/ниток**. Додати їх у UI редактора «всі характеристики» без механіки = лише підписи; обіцяти ефект у бою — **не можна** без окремого wiring.

### 1.5 Android / файли й зображення (перевірений стан репо)

| Шлях | Факт у проєкті |
|------|----------------|
| `user://` (сейви, settings) | Працює; **без** спеціальних permissions у `export_presets.cfg` |
| Зовнішнє сховище / SAF / share sheet | **Не реалізовано** в коді гри |
| `FileDialog` native Android | У коді **немає**; у Godot 4.x загалом є SAF-діалоги — **потрібно окремо перевірити на пристрої** перед обіцянкою «експорт у Завантаження» |
| Вибір зображення з галереї / файлів | **Не реалізовано**; той самий клас ризику, що й JSON import (тимчасові `content://` URI) |
| Permissions у пресеті | `custom_permissions` порожній; шаблони 4.7.2 debug/release є |
| WebView / вбудований HTML-редактор | **Немає** залежності WebView у проєкті |
| Поширення файлу (Intent share) | Немає |
| Декодування зображень у грі | Є лише внутрішні `Image`/`ImageTexture` (UI/арт); **немає** пайплайну «файл користувача → текстура редактора» |

**Формати (очікування Godot 4.7, не протестовано в цьому APK на телефоні):** типово PNG / JPEG / WebP (іноді BMP). SVG як растр «як є» **не** планувати без окремої залежності. Після імпорту — **скопіювати байти** у `user://…` і далі вантажити лише звідти (Android URI після закриття пікера часто протухає).

**Пам’ять / розміри (план обмежень, не імплементація):** на телефоні повнорозмірні фото легко з’їдають RAM. Рекомендована політика імпорту: даунскейл longest side (кандидат **2048 або 4096 px** — обрати після профілю на mid-range Android), зберігати внутрішню копію як **WebP або PNG**, тримати в редакторі одну `ImageTexture`. Відхиляти/попереджати файли понад ліміт МБ. Точні ліміти — замір на девайсі; **не обіцяти** «будь-яке 12K фото».

**Висновок для APK:** надійний мінімум без нових permissions — чернетки (JSON + **локальна копія фону**) у **`user://tree_drafts/`** + буфер для тексту. Пікер зображення/файлів — лише після **реального тесту на Android**; доти можна підкладати фон з `user://` / debug-асетів на ПК.

### 1.6 Меню гри

`title_screen.gd`: Продовжити / Нова гра / Слоти — **пункту «Редактор Древа» немає**.

## 3. Єдиний реєстр характеристик (обов’язково)

Мета: припинити дрифт HTML ↔ GDScript.

Пропозиція артефакту (наступна фаза):

- `data/stat_registry.json` **або** `scripts/data/stat_registry.gd` як єдине джерело:
  - `id`, `ua_template`, група (атака/захист/ресурс/…), `unit` (`flat`/`pct`/`flag`/`seconds`), `editor_min`/`editor_max` (м’які підказки), `applies_to`: `tree_node` | `nauz_mod` | `weapon_field`, `mechanics`: `wired` | `display_only`.
- `PerkTree.STAT_TEXT` / HTML `STAT_KEYS` **генеруються** з реєстру (скрипт у `tools/`), тест «реєстр == гра == редактор».

**Не** додавати в реєстр «усі мислимі» статы як wired без механіки. Для display_only — показувати в редакторі з міткою «поки лише опис / без ефекту в бою», щоб не обманювати.

### 4.4 Фон-шаблон для трасування вузлів (вимога t76)

Користувач імпортує **картинку Древа** і розставляє вузли/зв’язки **поверх** неї (як калька).

#### Обов’язкова модель координат

| Правило | Деталі |
|---------|--------|
| **Той самий world transform**, що й вузли/ребра | Ніколи не малювати фон як чистий screen-space overlay/`Control` поверх камери. |
| Формула (як у грі) | `screen = (world - center) * zoom + viewport/2` — і для кутів зображення, і для вузлів (`PerkTreeView.to_screen` / HTML `w2s`). |
| Параметри фону в **world units** | `origin_x`, `origin_y` (кут або центр — зафіксувати в meta), `width`, `height` у координатах Древа (після ×10). |
| Pan / pinch zoom | Змінюють лише `center`/`zoom` камери → фон і вузли зсуваються **ідентично**, відносний дрейф = 0. |
| **Lock** позиції/розміру | Блокує жести/поля, що змінюють `origin_*` / `width`/`height`. **Не** блокує спільний pan/zoom. |
| Visibility / opacity | `visible: bool`, `opacity: 0…1` (слайдер). Ховання фону не ховає вузли. |
| Width/height + preserve-aspect | При увімкненому aspect зміна однієї сторони перераховує іншу за співвідношенням пікселів текстури. |
| Режими редактора | Окремий підрежим або явні ручки «рухати/масштабувати фон» лише коли lock знято — щоб не плутати з рухом вузлів. |

Анти-патерн: `TextureRect` на весь екран з окремим scroll — **заборонено** для цієї фічі.

#### Persistence (окремо від runtime schema Древа)

- **`perk_tree.json` / формат v4 не розширювати** обов’язковим фоном (гра його не читає).
- Editor **project/draft** поруч із JSON, напр.:
  - `user://tree_drafts/<id>/tree.json` — той самий schema Древа;
  - `user://tree_drafts/<id>/project.json` — `{ "background": { "file": "bg.webp", "origin_x", "origin_y", "width", "height", "opacity", "visible", "lock_transform", "preserve_aspect" } }`;
  - `user://tree_drafts/<id>/bg.webp` — **внутрішня копія** імпортованого зображення.
- При імпорті з Android URI: одразу `FileAccess` copy → `bg.*`; далі ніколи не читати тимчасовий URI.
- HTML-редактор (ПК): аналог у localStorage / поруч із файлом (`*.project.json` + asset), той самий world-space draw через `drawImage` + `w2s`.

#### Android image picker (оцінка, не обіцянка)

| Крок | Статус |
|------|--------|
| Godot `FileDialog` / SAF вибір зображення | У репо **немає** використання; потрібен тест на телефоні з 4.7.2 export |
| Копія в `user://` після вибору | Обов’язкова в дизайні (обхід протухання `content://`) |
| Галерея vs файловий менеджер | Залежить від ОС/пікера; план підтримує «будь-який readable stream → bytes» |
| Без пікера (MVP ПК / debug) | Завантаження з уже покладеного `user://` або res-тестового асета |

#### Тести (закласти в PHASE 2+)

1. Покласти фон; поставити вузол у відомий world-кут зображення; змінити pan/zoom (не менше 5 комбінацій) → екранна відстань вузол↔якірні кути фону стабільна (допуск ~1 px).
2. Lock on: pan/zoom працюють; спроба drag фону / зміна size не змінює meta.
3. Preserve-aspect: зміна width оновлює height пропорційно pixel aspect.
4. Opacity/visibility: не впливають на hit-test вузлів (клік крізь прозорий фон — політика: фон не їсть кліки, або їсть лише в режимі edit-bg).
5. Закрити редактор → відкрити draft: фон на місці без зовнішнього URI.
6. Export «лише tree.json» для гри **без** обов’язкового фону; project+bg лишаються в draft.
7. (Android device) import → kill process → reopen draft; великий файл → warning/downsample.

#### Складність фічі

**Середня** для world-space draw + meta + copy; **вища**, якщо відразу тягнути неперевірений Android picker. Не плутати з механікою характеристик.


## 5. Оцінка складності (якісно)

| Блок | Складність | Примітка |
|------|------------|----------|
| Спільний реєстр + тести sync | **Низька–середня** | Багато вигоди, мало ризику |
| Нативний viewer+edit stats/links на базі `PerkTreeView` | **Середня–висока** | Найбільший шмат UX |
| Чернетки `user://` + backup/apply | **Середня** | Критично для безпеки прогресу |
| Parity з HTML undo/search/validation | **Середня** | Логіка вже є в JS — портувати |
| Фон-трасування world-space + lock/opacity/aspect | **Середня** | Критично: один transform з вузлами; copy в draft |
| Android SAF / image picker / share | **Висока / невизначена** | Потрібен девайс-тест; не блокує MVP на `user://` + тестовий асет |
| Довести всі `registry_display_only` до механіки | **Окремий великий епік** | Не частина «редактора» |

## 6. Критерії готовності (коли робитимемо runtime)

- Каталог і гра/редактори збігаються за ключами `tree_node`.
- In-APK: відкрити з меню, змінити вузол/зв’язок, зберегти чернетку, валідація, undo; на 1024×473 дії видимі.
- Apply не мовчки; backup існує; сейв героя не змішується з чернеткою.
- HTML round-trip і `tests/run_all.sh` зелені; **кількість вузлів shipped tree не зросла**.
- README містить секцію компонента з посиланням на docs.
- Android file «назовні» — або протестовано, або чесно задокументовано як обмеження MVP.
- Фон (t76): world-space; alignment-тести pan/zoom; lock не ламає камеру; draft reopen з внутрішньої копії зображення; `perk_tree` schema гри без обов’язкового фону.
