## 2. Єдина зміна в грі: вплітання ниток (пункт t61)

### Було

`scripts/ui/inventory_screen.gd`, функція `_on_attach_thread()` завжди брала
**перший науз у сумці**:

```gdscript
func _on_attach_thread() -> void:
	var nauz_i := -1
	for i in range(GameState.bag.size()):
		if Nauzi.is_nauz(GameState.bag[i]):
			nauz_i = i
			break
	if nauz_i < 0:
		return
	GameState.attach_thread(nauz_i, _sel_bag)
	_sel_bag = -1
	_refresh()
```

Гравець вибирав нитку, тиснув «Вплести нитку» (у меню «Ще ▾») — і вона йшла
в перший-ліпший науз, а не в той, що обраний на вкладці «Наузи». Крім того,
не було жодного повідомлення, чому вплітання не сталося.

### Стало

```gdscript
func _on_attach_thread() -> void:
	# Нитка з _sel_bag → в ОБРАНИЙ науз (вкладка «Наузи»), інакше — перший у сумці.
	if _sel_bag < 0 or _sel_bag >= GameState.bag.size():
		return
	if not Nauzi.is_thread(GameState.bag[_sel_bag]):
		return
	var ti := _sel_bag
	if _sel_nauz_uid > 0:
		var found: Dictionary = GameState.find_nauz_by_uid(_sel_nauz_uid)
		if found.is_empty():
			_status_nauz("Обраний науз не знайдено — обери його на вкладці «Наузи».")
			return
		var idx := int(found.get("index", -1))
		var ok := false
		if str(found.get("where", "")) == "socket":
			ok = GameState.attach_thread_to_socket(idx, ti)
		else:
			ok = GameState.attach_thread(idx, ti)
		if ok:
			_sel_bag = -1
			_refresh()
		else:
			_status_nauz(GameState.last_error if GameState.last_error != "" else "Не вдалося вплести.")
		return
	# запасний шлях — перший науз у сумці (як було)
	...
```

### Що це дає

1. Вплітає в **науз, обраний на вкладці «Наузи»** (`_sel_nauz_uid`,
   `GameState.find_nauz_by_uid`).
2. Працює і для науза **в гнізді героя** (`attach_thread_to_socket`), а не лише
   в сумці.
3. Показує **причину відмови** (`GameState.last_error`) замість тиші.
4. Запасний шлях лишено — якщо нічого не обрано, поводиться як раніше
   (сумісність зі звичкою гравця).

### Сумісність

- Збереження не змінюються (`SAVE_VERSION` не чіпали).
- `GameState.attach_thread`, `attach_thread_to_socket`, `find_nauz_by_uid` — уже
  існували, нічого нового в `GameState` не додано.
- Формат даних не змінювався.

## 6. Дизайн дерева: три знахідки

З аналізу `data/perk_tree.json` (922 вузли, 1093 зв'язки):

1. **43 унікальні описи на 922 вузли.** «Гілка.» повторюється **477 разів**,
   «Сплетення шляхів.» — 145, «Стовбур роду — сплетення шляхів.» — 74.
2. **Крона нерівна:** по висоті 231 · 185 · 121 · **91** · **182** · 112 —
   провал у четвертій смузі й сплеск у п'ятій.
3. **Спеціальних вузлів мало:** 15 notable + 8 keystone на 895 малих (2.5 %),
   і вони розкидані, а не зібрані в «грона».

### Пропозиція (повністю в `docs/perk_tree_design_v5.md`)

- Профіль тірів: **3 · 60 · 150 · 300 · 260 · 150** (разом 923) замість
  наявного 231 · 185 · 121 · 91 · 182 · 112.
- «Гроно» = notable-ядро + кільце 8–12 малих навколо, з'єднане зі стовбуром
  одним «стеблом».
- Валюта: small = 1 очко, notable = 4 (+умова), keystone = 8 (+ціна),
  core = 12, start = 0.
- Правила зв'язків: ступінь 1–4 (середній 2.3–2.5), жодного вузла зі ступенем 0,
  тупиків ≤ 15 %, міжрегіональні зв'язки лише в стовбурі.
- Описи **генерувати з бонусів** шаблоном, щоб прибрати «Гілка.» назавжди.

## 10. Застереження

- Не запускати `tools/sync_editor_tree.py` без змін у `data/perk_tree.json` —
  це зайве переписування вбудованого дерева.
- Не змінювати `SAVE_VERSION` для правки ниток — вона не чіпає збережень.

- Тест `tools/tree-editor-v5/test.js` потребує `jsdom` (`npm install jsdom`),
  у CI він не входить — це окремий, ручний тест.
